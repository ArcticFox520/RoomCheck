# 已知限制（KNOWN_LIMITATIONS）

本文件如实记录当前交付版本的边界、环境限制与未覆盖项。

## 1. 环境与验证边界

- **本地无 Docker daemon**：本仓库在开发环境无法执行 `docker build` / `docker run`；Dockerfile 与 Compose 通过静态审查，多架构镜像由 GitHub Actions 构建验证。发布前应在 CI 中确认镜像构建、manifest 与启动冒烟测试通过。
- **arm64 二进制未在本机运行**：本机为 x86_64，arm64 静态二进制已完成交叉编译并校验架构/静态链接，但未在本机执行；CI 在 arm64 Alpine 容器（QEMU）内构建并执行 `--version`、`--selftest`。
- **浏览器兼容性**：前端针对现代浏览器（Chrome/Edge/Firefox/Safari 近两年版本）实现，使用 CSS 变量、`fetch`、`XMLHttpRequest`、`<dialog>` 之外的普通 DOM；未适配 IE。
- **截图**：`docs/screenshots/` 若存在则为无头 Chromium 生成；不同系统字体渲染可能略有差异。

## 2. 业务与数据模型边界

- 每个楼层长只配置**一个楼栋的连续起止寝室范围**。需要覆盖多个楼栋时，应创建多个楼层长账户。工作指导中的 Config Agent 定义为单一 `building_name`。
- 楼栋名称是 `room_key` 的一部分；**修改楼栋名称会被视为全部寝室移出 + 新增**，原备注/图片保留但显示为“移出范围”的孤立数据，可由管理员手动删除。这是工作指导“room_key 由楼栋名称和寝室编号构成”的直接结果。
- 寝室编号按字符串保存；仅当起止寝室号均带相同宽度的前导零时才按该宽度补零，其余按普通数字显示。
- 系统不保留历史周计划：周重置会删除旧周排班/勾选/备注/图片记录（图片文件同步删除），只保留当前周。工作指导未要求历史归档。
- 同一自然周内多次“开始新一周”会替换当前计划，而非追加。
- 跨周未查完会继续显示旧周计划，直到楼层长手动重置；系统不会自动清空或自动创建新周计划。跨周后、重置前的“重新生成本周”和范围修改作用于该活动计划（仍显示旧周日期）；只有“开始新一周 / 重置本周”会创建当前自然周的新计划。
- 管理员不能创建第二个管理员账户；管理员密码只能通过自身改密或 `ADMIN_RESET=1` 重置。
- 不提供数据导出 UI（按工作指导冻结）。
- 账户删除后 72 天内可撤销；撤销不恢复旧 Session，用户需重新登录。
- 图片与备注的关联为可选项：只有上传时携带 `note_id` 的图片会随备注删除；普通寝室图库图片不会因删除某条备注而删除。
- 管理员“移出范围”数据（孤立备注/图片）只能查看和删除，不能编辑或迁移回当前周。
- 日志按自然周保留：周一 00:00 后删除上周之前的日志；恢复备份会把日志回滚到备份时点（数据库整体恢复），恢复动作本身会写入新日志。
- 恢复备份是整库恢复：账户密码、会话、配置、排班、备注、日志等都会回到备份时点；管理员密码可能因此回退。
- 管理员概览的日期统计不接受周四（隐藏查寝日）；详情页日期筛选只提供六个查寝日。

## 3. 并发与部署

- 单实例部署：SQLite 单写连接 + 全局锁。不支持同一数据卷多实例同时运行。
- 备份/恢复期间 API 写入会被阻塞，恢复会关闭并重新打开数据库；请求可能等待数秒。
- Docker 镜像以非 root 用户运行，`/data` 卷需由镜像初始化或由部署方赋予写权限；`docker-compose.yml` 使用命名卷并启用 `read_only` + `no-new-privileges`。
- 容器仅提供 HTTP；HTTPS、HSTS、访问控制在外部反向代理配置。HTTPS 部署应设置 `ROOMCHECK_COOKIE_SECURE=1`。
- Docker Hub 仓库显示名为 `ArcticFox520/RoomCheck`，Docker 引用必须使用小写 `arcticfox520/roomcheck`。
- 镜像 `latest` 仅跟随稳定 semver Tag；生产应固定版本或 SHA，禁止使用 `main`。
- 每日备份在 03:00 后或服务启动时补做；如果服务整日未运行，则当天没有备份。
- 恢复备份后所有会话失效，当前管理员需重新登录。
- 备份保留最新 3 份正式备份；另有最多 2 份恢复前快照（不计入 3 份），会额外占用磁盘。
- 图片/备份占用磁盘空间未做配额限制；建议通过监控和卷扩容管理。

## 4. 安全边界

- 登录错误锁定计数只在内存，服务重启会清零（工作指导明确要求）。
- 登录失败审计会记录尝试的账户名与 IP，不记录密码。
- 管理员查看备注/原图的审计按“动作”记录，不保存备注正文或图片内容。
- 上传文件只做扩展名、MIME、签名黑名单与图片识别；未接入病毒扫描引擎。生产可按需扩展黑名单或接入杀毒服务。
- CSP 允许同源脚本与内联样式；前端所有用户内容均通过文本转义或 `textContent` 输出。若后续引入第三方 CDN/统计脚本，需要同步调整 CSP。
- 未实现多因素认证、密码找回、邮件通知。
- 备份文件包含数据库与密码哈希，应限制备份卷访问权限。

## 5. 已知测试缺口

- 自动备份的“每日 03:00”时间边界未在真实时钟下等待验证；通过启动补偿与手动备份/保留策略测试覆盖。CI 时间不可控，未做 03:00 精确触发测试。
- 72 天到期通过直接修改 `delete_at` 模拟，未真实等待 72 天；撤销/到期/幂等/并发边界由数据库时间与重启场景覆盖。
- 恢复失败自动回滚路径未注入磁盘故障；正常恢复、会话失效、数据回滚已验证。
- 图片 50 张上限、10MB 上限、黑名单、签名校验已覆盖；未做超大并发上传压力测试。
- Docker 多架构构建、镜像运行、Healthcheck 只在 CI 中验证（本机无 Docker）。
- CSS 孤儿检查为静态正则分析；极端动态拼接的类名可能需人工复核。当前检查结果见验收报告。

## 6. 交付物说明

- `database/schema.sql` 为运行 Schema 的参考副本，实际初始化由后端内嵌 SQL 执行；修改 Schema 时需同步两处。
- `third_party/sqlite/` 为 SQLite 官方 amalgamation 源码，随仓库分发以保证静态构建可复现。
- 测试使用临时数据目录并自行启动/停止服务，不会修改生产数据。
